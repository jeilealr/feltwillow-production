# Image prompts: one source of truth, templates and lint

**Scope:** this is the prompt-manifest implementation for stories that
actually have `prompt_manifest.json` (such as Lion and Mouse v5 and Ugly
Duckling v1). Current Lion and Mouse v6 uses story-local scene, staging,
keyframe and boundary plans plus a hash-bound visual-review ledger. For v6,
read [its current packet](../stories/lion_and_mouse_v6/README.md) and run
`production/keyframe_visual_gate.py --story lion_and_mouse_v6` and
`production/v6_runtime.py --story lion_and_mouse_v6 --preflight` instead of
manifest `build`/`lint`/`approve` commands.

Every image and video prompt of a story is built from **one visual bible** so that a character,
a background and a size relation are described with the same words everywhere. This page is
the reference for the data and the tool; the step-by-step workflow (new story, writing,
generating, review gate) is the repo skill
[`.claude/skills/consistent-image-prompts/SKILL.md`](../.claude/skills/consistent-image-prompts/SKILL.md),
and the rules with their evidence are in [`creation-rules.md`](creation-rules.md) CR-11 to CR-19.

## Why

Before 2026-10-02 each v4 prompt carried its own copy of the character text, and later
corrections lived in separate revision files. Copies drifted: one record said
"burnt-orange/rust mane", another "rust mane", a third added "not crimson"; Milo was
"taupe-grey" in one place and "warm taupe" in another; size numbers in the prompts (Milo 0.18
of the frame on the trap path) contradicted the accepted frames (0.33-0.36). Images followed the
words and drifted with them. Now each fact exists once, and `lint` fails when a prompt states
a character fact anywhere else.

## Files

| File | Role |
|---|---|
| `stories/<slug>/visual_bible.json` | the source of truth (schema below) |
| `stories/<slug>/prompt_manifest.json` | `images[]` records and `shots[]` video plans, each prompt stored as a template plus its rendered text |
| `stories/<slug>/prompts/*.md` | readable copies, regenerated by `md`; never edit |
| `production/image_prompts.py` | `lint`, `build`, `show`, `md`, `review`, `new-story` |

## Bible schema

| Key | Content |
|---|---|
| `characters.<id>` | `name`; `canonical` (path) and `canonical_record` (manifest id); `identity` (full description written from the canonical, with colour hex codes, proportions and feature counts); `sheet` (one-line predicate) and `short` (`"<Name> is <sheet>..."`) for video prompts; `mouth` (approved open-mouth design); `palette` (hex per part), `proportions`, `checklist` (review items), `drift_phrases` (words a prompt may never contain) |
| `cast_scale` | the story-wide size rule (v4: Milo standing = 0.55 of Leo's mane height, decided 2026-10-02), its lineup frame and the sizes measured before |
| `locations.<id>` | `description`, `landmarks` (normalised positions), `light`, `plate` (approved empty plate), `ambient` (video motion) |
| `setups.<id>` | one camera setup: `location`, `framing` (CR-15), `label`, `camera`, optional `background_treatment` (e.g. the strong blur of a close-up), `size` (`{<char>: sentence}`, measured frame fractions on the anchor; only the characters in a frame are rendered), `relation` (comparison sentence, rendered when two characters share the frame), `anchor_record` (the approved frame the sizes were measured on; attached to every start frame as its size anchor) |
| `blocks.<name>` | shared text: `style`, `light_and_colour`, `cast_scale`, `final_check`, edit instructions, studio and plate rules, prop and world-state rules |
| `generic_blocks` | the blocks a new story copies |
| `reference_roles.<role>` | the plain sentence that tells the image model what an attached reference is for |
| `lint` | `forbidden_in_prompts`, `allow_phrases`, `warn_words` |

## Templates and placeholders

An image record stores `prompt_template`; `build` renders it into `positive_prompt`, which is
what a tool receives. Video variants store `positive_prompt_template` and
`full_prompt_specification_template` in the same way.

| Placeholder | Renders |
|---|---|
| `{{identity:<char>}}` | the full canonical description |
| `{{short:<char>}}` | the one-sentence description (video) |
| `{{mouth:<char>}}` | the approved open-mouth design (open-mouth studies and `<shot>_open` key frames) |
| `{{setup:<id>}}` | camera, background (plate description, landmarks and light; close-ups get the blur treatment and no landmark list) and the measured sizes of the characters in this frame |
| `{{plate:<loc>}}` | the location alone (plates, video backgrounds) |
| `{{block:<name>}}` | a shared block |
| `{{refs}}` | the attached references, numbered in attachment order, each with its role sentence, the referenced record's `label` and the file name |
| `{{frame}}` | this record's `frame` text (what the frame shows); `{{frame:<record>}}` in a video prompt gives its start or end image's text, so video and stills say the same |

The record's own words describe only what belongs to that frame: pose, position (x/y
fractions), expression (brows, eyes, mouth), action and prop state. A scene template reads,
in order: frame line, `{{refs}}`, edit instruction for end frames, cast line,
`{{identity:...}}` per visible character, `{{block:cast_scale}}` when two or more characters
share the frame, `{{setup:...}}`, `{{block:light_and_colour}}`, world-state blocks and state,
`This frame shows: {{frame}}.`, `{{block:style}}`, `{{block:final_check}}`.

Reference order (one order for every prompt): the edit base or previous accepted frame, the
locked plate, the canonicals, pose, expression, mouth and prop references, the size anchor,
framing, camera-geometry and staging references. A reference that shows a character absent
from the frame is not attached (staging images excepted).

Reference roles: `edit_base`, `identity_root`, `locked_plate`, `world_state`,
`camera_geometry`, `framing`, `expression`, `pose`, `prop`, `mouth_design`, `staging_only`,
`size_anchor`.

## Open-mouth key frames for talking clips (CR-19)

A `mouth` (talking) video variant animates between two key frames only, so the open mouth must
be one of them or the model invents a different open shape each render. Every dialogue close-up
with a `mouth` variant therefore has an extra scene record `<shot>_open`: an edit of the shot's
closed start frame (`{{block:edit_open_mouth}}`, so the start frame is the `edit_base`) that
opens only the mouth to the character's approved speech shape. It attaches the closed start
(`edit_base`), the character's canonical (`identity_root`) and the character's open-mouth study
`*_OPEN` (`mouth_design`), and repeats `{{mouth:<char>}}`. Each variant carries its own
`start_image`/`end_image`: `closed` runs start→end; `mouth` runs start→`<shot>_open`.
`production/export_runtime.py` reads these per-variant endpoints and freezes both key frames per
variant, so the talking clip always resolves to the one approved open mouth.

## Lint rules

`python3 production/image_prompts.py lint` exits 1 on any error:

- a rendered prompt differs from its template (someone edited the output, or the bible changed
  without `build`);
- a visible character lacks exactly one `{{identity:...}}` (images) or `{{short:...}}` and
  `{{identity:...}}` (video), or an identity block names a character that is not counted;
- **identity conflict**: a sentence outside the canonical blocks pairs a colour word with a body
  feature (e.g. "his rust mane", "brown eyes"), which would be a second description;
- a drift phrase (bible `drift_phrases`, `lint.forbidden_in_prompts`) appears in any prompt or block;
- the bible contradicts itself: `short`/`sheet` uses a colour the full identity does not;
- a scene record has no single `{{setup:...}}`, its `framing` differs from the setup's, or the
  start and end of a shot use different setups;
- an end frame's first reference is not its start frame;
- references: a record that attaches images lacks `{{refs}}`; a role is unknown; a visible
  character's canonical is not attached; a canonical is attached for a character that is not in
  the frame; a referenced record points to an old revision; a file is missing; an older-version
  (`/v3/`) image is attached other than as `staging_only`, `expression` or `camera_geometry`;
- a template edits the first image (an edit block, including `edit_open_mouth`) but that reference
  is not `edit_base`;
- a scene record lacks its `frame` text, or its wide or two-shot setup has no measured size for a
  visible character; a setup's `anchor_record` is missing or belongs to another setup;
- a video prompt uses `{{frame:...}}` of an image other than its own variant's start or end
  (the `mouth` variant's end is the shot's `<shot>_open` key frame, not `<shot>_end`);
- doubled punctuation from a block joined to template text.

## A new story's first packet

`python3 production/story_packet.py stories/<slug>/packet_source.py` turns one source file (script lines,
characters, size lineup, places, camera setups, shots with start and end frames, expressions, poses, props)
into the bible, the manifest with every image and video template, `dialogue_coverage.json` and
SCRIPT/SHOT_PLAN/README. Examples: `stories/tortoise_and_hare_v1/`, `stories/boy_who_cried_wolf_v1/`. It
overwrites the bible and manifest, so it is for planning only; once images are accepted, edit those files.

## Commands

```bash
python3 production/image_prompts.py lint                  # 0 errors before any generation
python3 production/image_prompts.py build                 # after editing the bible or a template
python3 production/image_prompts.py show s14_opening_start  # template and rendered prompt
python3 production/image_prompts.py md                    # refresh prompts/*.md
python3 production/image_prompts.py review s14_opening_start --image candidate.png
python3 production/image_prompts.py --story <slug> new-story <new_slug>
```

`review` writes `work/review/<record>.jpg`: the canonicals, any expression reference, the
setup's size anchor, the locked plate and the previous shot's end frame above, and the candidate
with a 0.1 grid below, for the side-by-side gate in the skill.

When the owner asks the agent to generate, the built-in OpenAI `image_gen` tool is the default;
Gemini via `character/gemini_image.py` is optional when the owner selects it and API access is
configured. In either case, start from the rendered prompt and attach only the record's listed
references in order. Record the actual tool, exact prompts, references, output path and hash in
the manifest. For ImageGen, copy the selected output from its generated-images cache to the
record's exact target; keep a raw source in `.review/` if normalization is needed.

## Decisions recorded in the bible

- **Leo-to-Milo ratio (decided 2026-10-02).** Milo standing = 0.55 of Leo's mane height, Milo's
  head about 0.4 of Leo's face height, as in `s05_nose_aftermath_start`. Setups whose old anchor
  shows another ratio keep that anchor for camera and Leo only (`anchor_note`); frames with both
  characters attach the lineup frame (role `size_lineup`).
